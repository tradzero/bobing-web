# 碗碰撞体问题诊断与修复方案

> 最后更新：2026-04-14
>
> 状态更新（2026-04-17）：当前运行时已采用 `HF_GRID_SIZE=51` 的 Heightfield 碗底，并使用 `bowlFloorMaterial` / `bowlWallMaterial` 分离碗底与挡墙材质。下文中关于 30×30 网格或 `bowlMaterial` 复用的内容，属于当时的设计估算或历史记录。

## 现象

用户测试中观察到三类异常：

1. **骰子嵌入碗壁** — 骰子落入碗中后卡在碗壁内部
2. **骰子无视碗碰撞飞到桌面** — 部分骰子穿过碗壁落到桌面上
3. **骰子被不可见的东西挡住** — 骰子在碗内空间被弹飞或悬停

经多轮修复（AABB 更新、Timer 首帧、旋转符号、碗壁几何参数），前两类问题频率显著下降但未完全消除。根本原因是**离散墙片近似曲面**这一方案存在结构性缺陷——墙片间必然有缝隙和边缘碰撞问题，增加片数只能缩小问题不能消除。

## 残留问题

修复后仍偶发骰子嵌入碗壁或飞出碗外。原因是离散墙片方案的结构性局限：

- 12 片 Box 之间存在物理缝隙，骰子边角可以卡入
- 碗底（Cylinder）到碗壁底部的过渡区无法完美衔接
- 直线倾斜面与视觉碗的抛物线曲面偏差较大（尤其碗下半段）

进一步增加墙片密度或多层碗壁只能缓解，维护成本持续偏高。

## 最终方案：Heightfield 隐形碗底 + 低矮挡墙

**核心思路**：视觉碗纯装饰不变，物理碗替换为 Heightfield 连续曲面 + 简单挡墙。

### 技术可行性验证

| 项目 | 结论 | 依据 |
|------|------|------|
| Heightfield 与 Box 碰撞 | ✅ 支持 | cannon-es.js:11311 `boxHeightfield` → 转发 `convexHeightfield` |
| Trimesh 与 Box 碰撞 | ❌ 不可用 | cannon-es.js:10393 `convexTrimesh` 被注释 |
| Heightfield 做碗底 | ✅ 可行 | 中心低、边缘高的抛物面，天然收拢骰子 |
| Heightfield 做碗壁 | ⚠️ 有限 | 单值高度函数，无法表示垂直面或悬垂结构；实际可用坡度取决于网格分辨率与数值稳定性 |

### 方案结构

```
视觉层（不变）        物理层（替换）
┌─────────────┐      ┌─────────────────────────┐
│ bowl.ts     │      │ Heightfield 碗底曲面     │ ← 连续、无缝、自然收拢
│ (LatheGeom)  │      │  中心低，边缘高          │
│             │      │  覆盖到碗壁坡度较陡处   │
│             │      ├─────────────────────────┤
│             │      │ 12-16 片竖直 Box 挡墙    │ ← 只防逃出
│             │      │  半径 < 视觉碗内壁       │
│             │      │  高度刚好超过碗口即可      │
│             │      ├─────────────────────────┤
│ table.ts    │      │ 桌面 Plane（兜底不变）    │
└─────────────┘      └─────────────────────────┘
```

### 实施细节

**1. Heightfield 碗底**

- 初版估算：约 30×30，`elementSize` 覆盖碗口直径（~2.4m / 30 ≈ 0.08m 间距）；当前实现已提升到 `HF_GRID_SIZE=51`，`elementSize≈0.052m`
- 高度函数：碗中心最低（y≈0），向外升高，拟合视觉碗 `bowl.ts` 的内壁曲线 `r = 1.2 * (y/0.7)^0.6 - 0.06` 的反函数
- Heightfield position 居中，使碗中心对齐原点
- 边缘坡度应平缓到碰撞数值稳定（初始调试目标 ~45°，最终由测试收敛），过陡部分由挡墙接管

**2. 低矮挡墙**

- 12-16 片竖直 Box，围成一圈
- 挡墙半径初始调试范围 ~0.9-1.0m（碗口处视觉内径 ~1.14m），最终由 T3 固定种子回归测试收敛
- 挡墙高度初始调试范围 ~0.15-0.3m（从 Heightfield 边缘高度向上延伸），最终由 T3 收敛
- 挡墙底部须与 Heightfield 边缘有足够重叠（埋入量），防止过渡区出现缝隙
- 挡墙只负责"拦住"，不参与碗底曲面拟合

**3. 接口兼容**

- 仍在 `bowl-body.ts` 中实现，导出同样的 `BowlBodies` 接口
- 视觉碗 `bowl.ts`、场景、引擎等模块不受影响
- 当前实现使用 `bowlFloorMaterial`、`bowlWallMaterial` 和 `tableMaterial`

### 相比离散墙片方案的优势

| | 离散墙片（当前） | Heightfield + 挡墙 |
|---|---|---|
| 碗底连续性 | 扁平圆柱 + 间隙 | Heightfield 连续曲面，无缝 |
| 碗壁覆盖 | 12 片倾斜 Box 拼接 | 挡墙只防逃出，不拟合曲面 |
| 嵌入风险 | 高（Box 边缘/缝隙） | 低（连续面无缝隙） |
| 飞出风险 | 中（依赖墙片覆盖度） | 低（连续碗底收拢 + 挡墙兜底） |
| 调参复杂度 | 高（5+ 耦合参数） | 低（高度函数 + 挡墙半径/高度） |
| 维护成本 | 高（参数与视觉碗手动对齐） | 低（高度函数可直接复用视觉碗曲线） |

### 测试计划

| 测试 | 内容 | 说明 |

| T1 | 挡墙几何正确性 | 墙薄轴沿径向、墙心在预期半径上、相邻墙片有足够重叠（无逃逸缝隙） |

### 风险与边界

- Heightfield 是轴对齐的矩形网格，不是真正的圆形碗底。网格外角区域可能需要裁剪或抬高处理
- `elementSize` 过大会导致碗底不够光滑，骰子可能在网格三角面边缘抖动
- 如果 Heightfield 性能表现不佳（碰撞检测频率高），可能需要降低网格密度
- Heightfield 边缘与挡墙底部的过渡区是新的风险点，须通过 T2 验证连续性
