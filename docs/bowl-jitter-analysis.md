# 碗底缓慢碰撞/抖动问题诊断与修复方案

> 最后更新：2026-04-14（v4，碗底曲线重构方案）
>
> 状态更新（2026-04-17）：当前运行时已是 `HF_GRID_SIZE=51`、`elementSize≈0.052m`，并且碗底/碗壁材质已拆分为 `bowlFloorMaterial` / `bowlWallMaterial`，接触参数为 `diceFloor` / `diceWall`。文中出现的 `31×31`、`0.08m`、`diceBowl`、`bowlMaterial` 等表述，若未特别注明“初版诊断”，都不应再视为当前实现。

## 现象

骰子落入 Heightfield 碗底后，视觉上已经"停了"，但仍然缓慢地微弹跳、滑动或抖动，持续数秒才最终结算。用户感知为"碗底缓慢碰撞"。

## 诊断

### 1. Heightfield 三角面边缘碰撞

初版诊断时 Heightfield 为 31×31 网格，`elementSize = 0.08m`。当前运行时已提升到 51×51，`elementSize ≈ 0.052m`，骰子边长 0.24m 覆盖约 4.6~5 个网格单元。

骰子在碗底时，底面跨越多个三角面。cannon-es 对 Box-Heightfield 碰撞的处理方式是将 Box 转为 ConvexPolyhedron，再对每个三角面做 separating-axis 检测。当骰子底面恰好跨两个三角面的**棱线**时，可能产生方向不一致的微小碰撞响应，导致骰子反复弹起一个极小高度。

碗底中心区域高度变化：

```
offset=0  h=0.00000m  slope=0.000
offset=1  h=0.01475m  slope=0.184
offset=2  h=0.03667m  slope=0.274
```

即使在最平坦的碗底中心，相邻网格点之间仍有 ~0.015m 高度差，三角面法线与水平面并非完全平行。

即便提升到当前的 `elementSize ≈ 0.052m`，网格单元边长与骰子底面 0.24m 之比仍只有约 1:4.6，三角面棱线离散感只是减轻，并未被根除。

### 2. 弹性恢复系数过高

当前运行时已经拆分为 `diceFloor.restitution = 0.15` 与 `diceWall.restitution = 0.15`。初版诊断里使用过统一的 `diceBowl.restitution = 0.3`，那个结论只适用于当时尚未拆材质、尚未降 restitution 的阶段。

**注意**：当前碗底和挡墙已经分离。碗底使用 `bowlFloorMaterial`，挡墙使用 `bowlWallMaterial`，降低 `diceFloor.restitution` 不会再直接改变墙面回弹。

### 3. Sleep 条件过严苛

```
sleepSpeedLimit: 0.1 m/s
sleepTimeLimit:  1.0 s   ← 骰子需持续1秒低于 0.1m/s 才能 sleep
```

碗底微弹跳的速度在 0.05-0.15 m/s 范围内振荡，恰好在 sleep 阈值附近反复进出，无法稳定进入 sleep 状态。

### 4. 阻尼比不足

```
linearDamping:  0.3
angularDamping: 0.3
```

线性阻尼 0.3 意味着每秒仅衰减 30% 速度。对于碗底微弹跳的低速振荡，阻尼衰减不够快，需要多秒才能降到阈值以下。

### 5. 停稳检测与 sleep 机制的竞争

停稳检测参数：
```
speedThreshold:  0.05 m/s
angularThreshold: 0.05 rad/s
stableDuration:  0.5 s
```

停稳检测的阈值 (0.05) 低于 sleep 阈值 (0.1)。当骰子速度在 0.05-0.1 区间振荡时，既不 sleep 也不停稳，形成"灰区"。

### 6. controller.onSettled 冻结时机

上一轮已添加了 `onSettled` 中冻结骰子的逻辑（`velocity.set(0,0,0)` + `sleep()`），但问题在于**冻结发生在结算之后**，而用户看到的抖动发生在**结算之前**——即检测到停稳之前的那段时间。

## 根因总结

| 因素 | 影响 | 严重度 |
|------|------|--------|
| Heightfield 离散分辨率仍有限（当前 51×51，elementSize≈0.052m） | 三角面棱线离散感仍是微弹跳源头 | ★★★ |
| Heightfield 三角面棱线碰撞 | 法线不一致导致微碰撞响应 | ★★★ |
| restitution 0.3 偏高（碗底+挡墙共用） | 微弹跳衰减慢 | ★★☆ |
| sleep timeLimit 1s 过长 | 延迟进入 sleep | ★★☆ |
| 线性阻尼 0.3 偏低 | 低速衰减慢 | ★★☆ |
| 停稳阈值与 sleep 阈值灰区 | 两个机制互相卡住 | ★☆☆ |

## 修复方案

### A. 提高 Heightfield 分辨率（从源头平滑三角面）

已将 `HF_GRID_SIZE` 从 31 提高到 51，使 `elementSize` 从 0.08m 降低到约 0.052m。骰子底面 0.24m 可覆盖约 4.6~5 个网格单元，三角面棱线密度更高、法线过渡更平滑，但这一步本身不足以完全消除 chamfer 弹跳。

```ts
// bowl-body.ts
export const HF_GRID_SIZE = 51  // 31 → 51
```

**优点**：最靠近根因的修复，不改曲线形状，不改碰撞参数  
**权衡**：碰撞检测计算量增加（三角面数从 ~1800 → ~5000，每个网格单元含 2 个三角面），但 Heightfield 只对局部三角面做检测，实际开销可接受  
**验证**：先只改此项，观察抖动是否显著缓解

### B. 碗底中心小平底 + 平滑过渡（消除碗底中心最后的微坡度）

在 Heightfield 高度生成中，碗底中心设一个小平底区 + smoothstep 过渡带，避免硬切边缘造出新的环形碰撞带。

```ts
const FLAT_RADIUS = 0.15    // 完全平坦区半径（较小，仅覆盖碗底最低点）
const BLEND_RADIUS = 0.35   // 从平坦过渡到曲线的混合区外边界
// d < FLAT_RADIUS → h = 0
// FLAT_RADIUS ≤ d ≤ BLEND_RADIUS → smoothstep 混合 (0 → bowlCurveHeight(d))
// d > BLEND_RADIUS → bowlCurveHeight(d) 原样
```

**优点**：碗底中心完全平坦，骰子静止时底面法线 100% 一致  
**权衡**：在 `BLEND_RADIUS` 处要确保 smoothstep 的曲率不会引入新的碰撞异常；FLAT_RADIUS 不宜过大（0.15m 处高度仅 ~0.03m，过渡落差小）  
**注意**：不能用硬切（`if d < R: h = 0`），否则在切割边缘产生 ~0.07m 环形台阶

### C. 降低碗体 restitution（减少微弹跳能量保留）

已将统一 `diceBowl.restitution` 拆解为 `diceFloor.restitution` / `diceWall.restitution`，当前默认均为 0.15。后续只需要单独扫 `diceFloor.restitution`，不再连带影响墙面回弹。

```ts
diceFloor: { friction: 0.28, restitution: 0.15 }
diceWall: { friction: 0.28, restitution: 0.15 }
```

**当前状态**：这个约束已经解除。碗底/碗壁分材质后，`diceFloor` 和 `diceWall` 已可独立调参。

**优点**：简单直接  
**权衡**：碗整体弹性感减弱；是否拆分材质由实际手感决定

### D1. 提高阻尼（加速低速衰减）

```ts
// config/physics.ts
diceLinearDamping: 0.5,     // 0.3 → 0.5
diceAngularDamping: 0.5,    // 0.3 → 0.5
```

**优点**：不改碰撞体形状，直接加速低速振荡衰减  
**权衡**：阻尼过高会影响骰子翻滚的自然感  
**验证**：先只调阻尼，用 T5 对比收敛帧数变化

### D2. 放宽 sleep 条件（降低 sleep 进入门槛）

```ts
// config/physics.ts
diceSleepSpeedLimit: 0.15,  // 0.1 → 0.15
diceSleepTimeLimit: 0.5,    // 1.0 → 0.5
```

**优点**：骰子更容易进入 sleep，减少"阈值附近反复进出"  
**权衡**：与阻尼调整效果可能叠加，需单独验证以隔离归因  
**验证**：在 D1 已实施的基础上追加，再用 T5 对比

### E. 停稳检测阈值微调（最后兜底，保守调整）

```ts
// config/settle.ts
speedThreshold: 0.08,       // 0.05 → 0.08（保守上调，靠近但不超过 sleep 阈值）
angularThreshold: 0.08,     // 0.05 → 0.08
stableDuration: 0.4,        // 0.5 → 0.4（微调）
```

**性质说明**：此方案本质上是"更早截断运动并冻结"，不是纯物理修复。提高阈值会在骰子仍有微弱运动时判定停稳，然后由 `controller.onSettled` 强制冻结。视觉上"更快停了"，但物理稳定性并未真正提升。

**优点**：消除 speed 0.05-0.1 灰区  
**权衡**：幅度必须保守，避免在骰子还在明显运动时就被截停  
**定位**：仅作为兜底手段，排在所有物理层修复之后

## 建议实施优先级

按从根因到兜底的顺序，**分步实施、逐步验证**：

| 优先级 | 方案 | 性质 | 说明 |
|--------|------|------|------|
| P0 | A（提高网格分辨率） | 物理根因 | 先只改此项，验证抖动是否显著缓解 |
| P1 | C（降低 restitution） | 物理参数 | 减少微弹跳能量，连同挡墙一起调（暂不拆材质） |
| P1 | D1（提高阻尼） | 物理参数 | 加速低速振荡衰减，单独验证效果 |
| P1 | D2（放宽 sleep 条件） | 物理参数 | 在 D1 基础上追加，隔离归因 |
| P2 | B（碗底小平底 + 平滑过渡） | 碰撞体形状 | 仅在 A 效果不够时追加 |
| P3 | E（停稳阈值微调） | 检测层兜底 | 最后手段，幅度保守 |

预期效果：碗底抖动从数秒缩短到 < 1 秒，用户体感"骰子落碗即停"。

## 回归测试策略

### 现有测试影响

- T3 固定种子模拟：参数变更后骰子运动轨迹改变，种子结果可能变化，需重新验证
- T4 Heightfield 高度校验：网格分辨率变更会改变数据维度和 elementSize；如加入平坦区，中心区域高度分布变化
- 停稳测试：阈值变更需同步更新 `settle.test.ts` 中的预期

### 新增：收敛时间回归测试（T5）

现有 T3 只验证终态位置（骰子是否在碗内），**不度量收敛速度**。需要新增一个固定种子下的"收敛时间"测试，用以区分"物理更稳了"还是"更早冻结了"。

```
T5: 固定种子收敛时间测试
- 使用固定种子投掷 6 颗骰子
- 每帧记录所有骰子的最大线速度和最大角速度
- 收敛条件：所有骰子线速度 < 0.05 m/s 且角速度 < 0.05 rad/s（纯物理收敛，不含 sleep/freeze）
- 测量从投掷到满足收敛条件所需的帧数
- 两层断言：
  - 体验上限：收敛帧数 < 120 帧（2 秒），超过此值用户会感知为"慢"
  - 物理基线：记录当前版本的收敛帧数作为基线，后续调优应使此值下降（而非打平或上升）
- 参数调优后此帧数应下降（证明物理真的更快收敛，而非检测层提前截断）
- 注意：必须同时检测线速度和角速度，否则会出现"测试通过但画面仍在慢转"的假阳性
```

### 第一轮问题：真实结算路径仍有超时

使用真实 sleep + settle 路径测试（20 种子），当前配置（旧曲线 + sleep 0.15/0.5）有 **7/20 超时（35%）**。

超时根因分析：**不只是碗底中心微抖，更核心的是碗下半段偏陡导致骰子在坡面长期慢滑/慢转**。

当前曲线 `h = 0.7 * ((d + 0.06) / 1.2)^(5/3)` 的结构性问题：
- `+0.06` 偏移使 r=0 处已有 **7.6° 坡度**，碗底没有真正平坦区域
- 指数 5/3 ≈ 1.67 太低，坡度增长接近线性：r=0.3 处 23.6°，r=0.5 处 30.3°

超时种子中卡住骰子分布在 r=0.05 ~ 0.74 全范围：

| 位置 | 坡度 | 典型角速度 | 种子 |
|------|------|-----------|------|
| 碗底中心 r<0.2 | 8~19° | 0.10~0.16 | 2, 42 |
| 中下半径 r 0.2~0.4 | 19~27° | 0.01~0.05 | 42, 3, 666, 111 |
| 中上半径 r 0.6~0.75 | 33~37° | 0.002~0.02 | 99999, 5000 |

### 第二轮（v4）：碗底曲线重构 + E2

#### 方案决策

1. **曲线方向**：纯幂函数零偏移 `(d/maxInnerR)^p`，不选分段曲线首发
   - 参数更少，几何行为更易解释，T4 更容易写稳定断言
   - 分段曲线（平底+混合+外段）耦合参数多，第一版上容易与 sleep/settle 交织难定位
2. **指数选择**：p=3.5
   - r=0.4 坡度 8.9°（目标 <10°），r=0.6 坡度 23.4°（明显陡坡推向外圈）
   - p=2.5 碗底不够平（r=0.4 17.7°），p=3 也偏陡（12.8°）
3. **曲线重构和 E2 同批实施**
   - p=3.5 单独上有回归（20 种子 3 超时，1000 种子超时率更高）
   - E2 单独上（旧曲线）也不够（20 种子 3 超时）
   - 两者叠加才能消除超时
4. **E1 暂不落地**，仅做后续体验层收尾备选
5. **T4/T5/T6 独立保留**，不合并
   - T4 改为几何不变量测试
   - T5 继续做纯物理收敛基线
   - T6 新增真实结算路径测试

#### 新曲线

```ts
// bowl-body.ts — 物理碗曲线重构
// 旧：h = BOWL_HEIGHT * ((d + BOWL_THICKNESS) / BOWL_RADIUS)^(5/3)
// 新：h = BOWL_HEIGHT * (d / maxInnerR)^3.5
export function bowlCurveHeight(d: number): number {
  const maxInnerR = BOWL_RADIUS - BOWL_THICKNESS  // 1.14
  const clamped = Math.max(0, Math.min(d, maxInnerR))
  return BOWL_HEIGHT * Math.pow(clamped / maxInnerR, 3.5)
}
```

|------|-------------|-------------|------|
| r=0.0 | **7.6°** | **0.0°** | 零偏移 |
| r=0.2 | 19.3° | 1.6° | -92% |
| r=0.4 | 27.2° | 8.9° | -67% |
| r=0.6 | 33.1° | 23.4° | -29% |
| r=0.8 | 37.9° | 41.6° | 外圈更陡→更好约束 |
| r=0.95 | 40.9° | 53.8° | 挡墙区高斜率 |

#### E2 参数

```ts
// config/physics.ts — sleep 放宽
diceSleepSpeedLimit: 0.25   // 0.15 → 0.25
diceSleepTimeLimit: 0.2     // 0.5 → 0.2
```

E2 参数核实过程（对 1000 种子大样本验证）：

| sleepSpeedLimit | sleepTimeLimit | 1000 种子超时数 | 最大帧数 |
|----------------|---------------|---------------|---------|
| 0.20 | 0.3 | 9 (0.9%) | 600 |
| 0.25 | 0.3 | 回退：9 种子中仍 6 超时 | 600 |
| 0.25 | 0.2 | 1 (0.1%) | 600 |
| 0.30 | 0.2 | **0** | 479 |

关键发现：**sleepTimeLimit 从 0.3→0.2 是消除顽固种子的核心**。坡面微振荡在 0.3s 内的尖峰反复重置 sleep 计时器，0.2s 窗口能在尖峰间隙捕获 sleep。

选用 `0.25/0.2`（1000 种子仅 1 超时，由 10s 兜底处理；0.30 可做零超时但更激进）。0.25 m/s 对应骰子每帧移动 <4mm + 旋转 <0.24°，视觉不可察。

#### 物理碗与视觉碗解耦

p=3.5 下物理碗比视觉碗在碗底更浅：
- 常驻区 r≤0.6 最大差值：0.177m
- 全域最大差值：0.197m @ r=0.75

**决策**：先接受解耦，作为 P0 物理修复。若镜头下差异明显，后续小幅跟随视觉内壁。不把"视觉碗不动"当长期方案。
